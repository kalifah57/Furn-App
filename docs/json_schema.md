# عقد الاستخراج الملزم — المخطّط وقواعد التصليب

> **U1 · المسار ٣ (الفهم)** · مقترح بانتظار اعتماد المؤسّس · **لا كود قبل الموافقة**
> DoD: «وثيقة معتمدة واختبارات الـparser تغطيها» — §٧ يربط كلّ قاعدة باختبارها.
> النصف الآخر من U1 في [`prompt_engineering.md`](prompt_engineering.md).
> التدقيق الذي بُنيت عليه: [`ai_audit.md`](ai_audit.md).

## ٠) ما معنى «ملزم» هنا

ثلاث درجات **لا تُخلَط**، وخلطها هو سبب أن العقد الحالي غير محروس:

| الدرجة | من يفرضها | قوّتها |
|---|---|---|
| **مضمون** | `StructuredResponseParser` — كود | يستحيل خرقه من مزوّد. **هذا وحده «ملزم»** |
| **مطلوب** | نصّ الـprompt | رجاءٌ يستجيب له نموذج مؤدّب ويتجاهله غيره |
| **قائم** | ما يفعله الـmock اليوم | خطّ الأساس، ليس عقدًا |

القاعدة الحاكمة: **ما لا يفرضه المُحلِّل ليس ملزمًا مهما تكرّر في الـprompt.**
لذلك كلّ التزام في §٣ أدناه مقترنٌ بموضع فرضه، أو يُعلَن صراحةً أنه غير مفروض بعد.

## ١) المخطّط — موثَّقًا مقابل الكود

مصدر الحقيقة هو النماذج المشتركة (يملكها المعماري)؛ هذا توثيقٌ لما تفكّكه
`FurnishingProject.fromJson` فعلًا وما يحقنه `kSchemaSkeleton` في الـprompt.

```json
{
  "project_id": "string",                  // ← الحقل الوحيد المحروس اليوم
  "locale": "ar-SA",
  "room": {
    "name": "string",
    "width_m": 0, "length_m": 0, "height_m": 0,   // أمتار (double) — لا سنتيمترات
    "room_type": "bedroom|living_room|guest_room|other"
  },
  "budget":   { "currency": "SAR", "max_total": 0, "flexible": false },
  "style":    { "preferred": [], "colors": [], "notes": "string" },
  "items": {
    "essential": [{ "type": "string", "constraints": [], "quantity": 1 }],
    "optional":  [{ "type": "string", "constraints": [], "quantity": 1 }]
  },
  "analysis": {
    "summary": "string",
    "missing_information": [],             // ← «المجهول يُعلَن» يعيش هنا
    "warnings": [],
    "confidence_score": 0
  }
}
```

### حقلان يقبلهما الكود ويُمنع أن يخرجا من الـLLM

| الحقل | من يملؤه فعلًا | الحالة اليوم |
|---|---|---|
| `recommendations {individual_items[], bundles[]}` | `recommendation_repository_impl.dart:42` | **يقبله `fromJson` من المزوّد — A-01** |
| `next_actions {ask_for_images, follow_up_questions[]}` | `business_rules_engine.dart:87` | **يقبله `fromJson` من المزوّد — A-03** |

### لماذا يقع عبء الرفض كلّه على المُحلِّل

`asString` / `asDouble` / `asInt` / `asStringList` / `asMapList` / `fromWire` كلّها
تُرجع افتراضيًّا ولا ترمي — قرار سليم للنماذج المشتركة (تفكيكٌ لا يتشظّى)، لكنه يعني
أن **أيّ تحقّق لا يعيش في `StructuredResponseParser` لا يعيش في أيّ مكان**.

## ٢) المضمون اليوم (٤ قواعد قائمة)

| # | القاعدة | الموضع |
|---|---|---|
| `H-01` | JSON غير قابل للتفكيك ⇒ `AiParsingFailure` | `structured_response_parser.dart:23` |
| `H-02` | إزالة الأسوار واستخراج أوّل كائن **متوازن** (لا `lastIndexOf('}')`) | `:51` |
| `H-03` | JSON صالح بلا `project_id` غير فارغ ⇒ رفض، لا مشروع فارغ صامت | `:43` |

### `D-1` — قرارٌ يحتاج ترجيحك

| | **(أ) رفض صلب** | **(ب) تجريد + تسجيل** |
|---|---|---|
| الحدّ | محفوظ | محفوظ |
| المستخدم | يخسر الاستخراج كلّه بسبب حقل واحد | يحصل على خطّته، والمحرّك يملأ التوصيات |
| الخطر | هشاشة تجاه مزوّد ثرثار | خرقٌ يمرّ بلا انتباه إن أُهمِل السجلّ |

**توصيتي: (ب) في التشغيل + (أ) في بوّابة اعتماد المزوّد.** المُحلِّل يجرّد دائمًا فلا
يعبر قرارٌ من الـAI، ويسجّل دائمًا فلا يكون الخرق صامتًا؛ وحزمة اعتماد المزوّد ترفض
رفضًا صلبًا فلا يُعتمَد مزوّد يقرّر. هكذا لا يدفع المستخدم ثمن سوء أدب المزوّد.

## ٤) المطابقة — الـmock طرفٌ في العقد لا خارجه

| الالتزام | الـmock اليوم | المطلوب |
|---|---|---|
| لا `recommendations` | ✅ لا يملؤه قطّ | يبقى |
| `missing_information` | ❌ **لا يملؤه أبدًا** (M-01) | يملؤه `H-15` في المُحلِّل — فيُصلَح للطرفين دفعةً واحدة |
| مجال الأبعاد | ❌ يقبل 400×600 (M-03) | `H-12` |
| ثقة صادقة | ❌ `0.7` على الفراغ (M-02) | `H-13` |
| `visionSummary` | ❌ يتجاهله (M-04) | خارج U1 — يُعالَج في U3 |

**قرار تصميمي:** أضع `H-12`/`H-13`/`H-15` في **المُحلِّل** لا في الـmock، لأن المُحلِّل
يقع على مسار المزوّدين كليهما. إصلاح الـmock وحده يترك المزوّد الحقيقي مكشوفًا؛
وإصلاح المُحلِّل يغطّي الاثنين — وهذا معنى أن يكون الالتزام «ملزمًا».

## ٥) ما يبقى خارج الضمان

**لا حتمية.** أيّ مزوّد LLM حقيقي غير حتمي، ولا حيلة تجعله كذلك. ما تضمنه هذه الطبقة
لأعلى ثلاثة أشياء لا رابع لها: **صحّة المخطّط · خلوّ المخرَج من قرار · إعلان المجهول
بدل تخمينه.** الحتمية تعيش في المحرّك، ويجب أن يُقرّ هذا قبل وصل أيّ مزوّد.

## ٦) ما لا يعرّفه هذا المستند

`FurnishingProject` عقدٌ مشترك يملكه المعماري (الميثاق §٥.١). كلّ ما سبق **توثيقٌ
لما يقرؤه الكود + تصليبٌ في طبقتي**. أيّ إضافة حقل (`schema_version` لـ`H-20`) تُقترَح
spec + PR.
