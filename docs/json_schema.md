# عقد الاستخراج — مخطّط JSON وقواعد التصليب

> المسار ٣ (الفهم) · **مقترح بانتظار الموافقة** — التصليب المقترح لم يُكتب كودًا بعد.
> يُرسمِن هذا المستند مرجعًا مذكورًا ٥ مرّات في `lib/ai/**` ولم يكن موجودًا (A-15).
> القسم ١ **توثيق للقائم**؛ القسم ٣ **مقترح إضافي** لا يعيد كتابة شيء.

## ١) المخطّط القائم — ما يقرؤه الكود اليوم

هذا ليس تصميمًا جديدًا: هو ما تفكّكه `FurnishingProject.fromJson` فعلًا، وما يحقنه
`kSchemaSkeleton` في الـprompt. **مصدر الحقيقة هو النماذج المشتركة (المعماري)،
وهذا المستند يوثّقها ولا يعرّفها.**

```json
{
  "project_id": "string",              // الحقل الوحيد المحروس اليوم
  "locale": "ar-SA",
  "room": {
    "name": "string",
    "width_m": 0, "length_m": 0, "height_m": 0,     // أمتار (double) — لا سنتيمترات
    "room_type": "bedroom|living_room|guest_room|other"
  },
  "budget": { "currency": "SAR", "max_total": 0, "flexible": false },
  "style": { "preferred": [], "colors": [], "notes": "string" },
  "items": {
    "essential": [{ "type": "string", "constraints": [], "quantity": 1 }],
    "optional":  [{ "type": "string", "constraints": [], "quantity": 1 }]
  },
  "analysis": {
    "summary": "string", "missing_information": [], "warnings": [],
    "confidence_score": 0
  }
}
```

### حقلان يقبلهما الكود ويجب ألّا يخرجا من الـLLM أبدًا

| الحقل | من يملؤه فعلًا | الحالة |
|---|---|---|
| `recommendations` `{individual_items[], bundles[]}` | `recommendation_repository_impl.dart:42` — محرّك التوصيات | **يقبله `fromJson` من المزوّد — A-01** |
| `next_actions` `{ask_for_images, follow_up_questions[]}` | `business_rules_engine.dart:87` | **يقبله `fromJson` من المزوّد — A-03** |

هذان هما موضع الخرق. المخطّط أعلاه لا يذكرهما، والـprompt يطلب تجنّبهما — لكن
**لا شيء في الكود يرفضهما**.

### طبيعة النماذج: متسامحة عمدًا

`asString` / `asDouble` / `asInt` / `asStringList` / `asMapList` / `fromWire` كلّها
تُرجع قيمًا افتراضية ولا ترمي. هذا قرار سليم للنماذج المشتركة (تفكيكٌ لا يتشظّى)،
**لكنه ينقل عبء الرفض بالكامل إلى المُحلِّل.** أيّ تصليب لا يعيش في
`StructuredResponseParser` لا يعيش في أيّ مكان.

## ٢) ما هو مُصلَّب اليوم فعلًا

| # | القاعدة | الحالة | الموضع |
|---|---|---|---|
| `H-01` | JSON غير قابل للتفكيك ⇒ `AiParsingFailure` | ✅ قائمة | `structured_response_parser.dart:23` |
| `H-02` | إزالة أسوار ```` ``` ```` واستخراج أوّل كائن **متوازن** (لا `lastIndexOf('}')`) | ✅ قائمة | `:51` |
| `H-03` | JSON صالح بلا `project_id` غير فارغ ⇒ رفض، لا مشروع فارغ صامت | ✅ قائمة | `:43` |
| `H-04` | مصفوفة جذرية (`[1,2,3]`) ليست مشروعًا | ✅ قائمة | `:36` |

القاعدة `H-03` قرار ممتاز موثّق في تعليق الملف، وهي **النموذج الذي يُقاس عليه** بقيّة
التصليب: *فشلٌ واضح خيرٌ من نجاحٍ صامت فاسد*.

## ٣) التصليب المقترح — إضافةً لا إعادة كتابة

كلّها داخل `StructuredResponseParser` (ملكي)، بلا لمس النماذج المشتركة.

| # | القاعدة | السلوك | يعالج |
|---|---|---|---|
| `H-10` | **`recommendations` من المزوّد لا تُقبَل** | انظر القرار `D-1` أدناه | **A-01** |
| `H-11` | **`next_actions` من المزوّد لا تُقبَل** | نفس `D-1` | **A-03** |

### `D-1` — قرارٌ يحتاج ترجيحك: رفضٌ صلب أم تجريد؟

عند وصول `recommendations` من المزوّد، أمامنا سلوكان:

| | **(أ) رفض صلب** `Err` | **(ب) تجريد + تسجيل** |
|---|---|---|
| الحدّ | محفوظ | محفوظ |
| المستخدم | يخسر الاستخراج كلّه بسبب حقل واحد | يحصل على خطّته، والمحرّك يملأ التوصيات |
| الرؤية | صاخب فورًا | مرئي عبر إشارة `contract_violation` لمسار ٥ |
| الخطر | هشاشة تجاه مزوّد ثرثار | خرقٌ متكرّر قد يمرّ بلا انتباه إن أُهمِل السجل |

**توصيتي: (ب) في التشغيل + (أ) في بوّابة قبول المزوّد.** أي: المُحلِّل **يجرّد دائمًا**
فلا يعبر قرارٌ من الـAI أبدًا، **ويسجّل دائمًا** فلا يكون الخرق صامتًا؛ وحزمة اختبارات
اعتماد المزوّد ترفض رفضًا صلبًا فلا يُعتمَد مزوّد يقرّر. هكذا لا يدفع المستخدم ثمن سوء
أدب المزوّد، ولا نغضّ الطرف عنه.

`(أ)` وحدها موقف دفاعيّ سليم لكنه يحوّل عيب المزوّد إلى عطل عند المستخدم.
**القرار لك؛ الفرق سطران في المُحلِّل.**

## ٤) الاختبار الذي يجب أن يحلّ محلّ الأجوف

`raw_llm_extraction_service_test.dart:74` يمرّر مخرَجًا **بلا** `recommendations`
فلا يثبت شيئًا (A-02). البديل يمرّر توصية فعلًا:

```
مخرَج المزوّد: {"project_id":"p1","recommendations":{"individual_items":[
                 {"name":"كنبة رمادية","price":2500}]}}
المتوقّع (ب):  الاستخراج ينجح · recommendations.isEmpty == true · إشارة خرق مسجّلة
المتوقّع (أ):  Err
```

بلا هذا الاختبار، أيّ تصليب نكتبه يمكن أن ينكسر لاحقًا بلا أن يلاحظه أحد.

## ٥) ما لا يعرّفه هذا المستند

`FurnishingProject` وحقوله عقدٌ مشترك يملكه المعماري (الميثاق §٥.١). كلّ ما سبق
**توثيقٌ لما يقرؤه الكود + تصليبٌ في طبقتي**. أيّ إضافة حقل (مثل `schema_version`
في النموذج نفسه لـ`H-12`) تُقترَح spec + PR ولا تُكتب من طرفي.
