# تناغم الغرفة — Room Harmony

> **التسليم ٣ من ٤.** درجة شفّافة على طريقة الثقة، بفجوات قابلة للتنفيذ، Dart صرف داخل المحرّك.

**المشكلة التي يحلّها:** اليوم كل درجة تُحسب لمنتج **معزولًا**
(`RecommendationScorer.score(p, ctx)` — منتج واحد). يمكن أن تكون كل قطعة ممتازة على حدة،
ومجموعها غرفة متنافرة، والأداة تقول «ثقة ١٠٠٪». `grep` على `cohesion|affinity|harmony` في
`lib/` يعطي **صفرًا** — بينما `docs/recommendation_engine.md:61` يحدّد `cohesion` كجزء معلن من
درجة الباقة منذ البداية. هذا التسليم ينفّذ ما هو مُعلن، ولا يخترع مفهومًا جديدًا.

## 2) الأبعاد الخمسة

| البعد | الوزن | يقيس | القواعد |
|---|:--:|---|---|
| `styleCoherence` | 30 | هل تتحدّث القطع لهجة واحدة؟ | متوسط التقارب الزوجي · X3 |
| `colorHarmony` | 25 | هل الباليت مبنيّ أم متراكم؟ | C1..C6 |
| `materialBalance` | 20 | هل الخامات تتكامل أم تتزاحم؟ | M1..M4 |
| `formBalance` | 15 | هل للغرفة إيقاع ارتفاع وكتلة؟ | S1..S4 |
| `intentMatch` | 10 | هل النتيجة هي ما طلبه المستخدم؟ | تقارب ستايل الخطة مع `StylePreferences.preferred` |

**لماذا الستايل أثقل من اللون؟** لأن خطأ الستايل لا يُصلَح بقطعة واحدة، وخطأ اللون غالبًا
يُصلَح باستبدال واحد. نُثقّل ما يصعب إصلاحه.

**لماذا `intentMatch` قائم بذاته؟** لأن غرفة متّسقة داخليًّا وغير مطابقة لما طلبه المستخدم
هي فشل — وهذا هو الفرق بين «متناغمة» و«متناغمة على ذوق شخص آخر».

## 3) الحساب — حساب صحيح بالكامل

```
subScore[d] ∈ 0..100                      // لكل بعد
applicable   = الأبعاد التي تنطبق فعلًا
score        = Σ(subScore[d] × weight[d])  ÷  Σ(weight[d])      // للأبعاد المنطبقة فقط
```

**لا فاصلة عائمة في أي خطوة.** القسمة الأخيرة `~/` (قسمة صحيحة). السبب مذكور في البريف:
`List.sort` غير مستقرّة، ومقارنة الأعداد العشرية مصدر عدم حتمية — نتجنّب الصنفين معًا.

**إعادة التوزيع لا التزييف:** إن لم يُعلن المستخدم تفضيلًا، لا ينطبق `intentMatch`؛ يُحذف وزنه
من المقام بدل منحه درجة مخترعة. التقرير يذكر البعد المحجوب باسمه.

### 3.1 خصومات القواعد

| البعد | القاعدة | الخصم |
|---|---|:--:|
| `colorHarmony` | **C2** تعارض الحرارة | **−60** |
| | **C1** كسر ٦٠/٣٠/١٠ | −25 |
| | **C3** عائلة لونية زائدة (لكل واحدة) | −20 |
| | **C6** تباين إضاءة ضعيف | −20 |
| | **C4** تشطيب معدني ثالث | −15 |
| | **C5** لون صائح ثالث | −15 |
| `materialBalance` | **M2** لا خامة ناعمة في غرفة جلوس | −30 |
| | **M1** نغمة خشب زائدة (لكل واحدة) | −25 |
| | **M3** خشونة تخالف الستايل | −20 |
| `formBalance` | **S1** كل القطع ثقيلة | −25 |
| | **S3** إشغال خارج `0.25..0.65` | −25 |
| | **S2** نطاق ارتفاع واحد | −20 |
| | **S4** سجادة أصغر من ثلثي المرساة | −15 |

`subScore = clamp(100 − Σ خصومات, 0, 100)`

**C2 هي الأثقل عمدًا:** تعارض الحرارة هو الخطأ الذي **يُرى فورًا** في الصورة ولا يعرف
المستخدم تسميته. هذا بالضبط ما تضيفه الأداة فوق ذوق الهاوي.

### 3.2 `styleCoherence` — لا خصومات بل متوسط

```
styleCoherence = متوسط styleAffinity لكل زوج قطع     // 0..100 أصلًا
```
ثم فجوة `X3` حين يهبط أكثر من زوج واحد تحت `55`.

## 4) الصدق قبل الرقم — `HarmonyReadiness`

**غرفة فيها قطعة واحدة متناغمة حتمًا. عرض «١٠٠٪» عليها كذب.**
مقتدين بـ `ArFitVerdict.roomUnknown` الذي يقول «قِس غرفتك أولًا» بدل اختراع حكم:

| الحالة | السلوك |
|---|---|
| `< 3` قطع | `notEnoughItems` — **لا درجة إطلاقًا** · «أضف قطعة أو اثنتين ليصير للتناغم معنى.» |
| قطع بلا وسوم تصميم | `insufficientData` — درجة جزئية + إعلان الأبعاد المحجوبة |
| `≥ 3` قطع موسومة | `ready` — درجة كاملة |

> **لا يوجد ١٠٠ مجّاني.** كما أن `_confidence` لا تمنح ١٠٠ إلا باستحقاق كل بند.

## 5) الفجوة القابلة للتنفيذ — `HarmonyGap`

| الحقل | الغرض |
|---|---|
| `dimension` | أي بعد تضرّر |
| `ruleId` | `'C2'`, `'M1'`… — يتتبّع إلى مواصفة لغة التصميم كما تتتبّع `KA-*` إلى قاعدتها |
| `reasonAr` | **جملة عربية واحدة** تشرح ما حدث ولماذا يهمّ |
| `gainIfFixed` | نقاط الدرجة الكلّية المستردّة — **الرقم الذي يجعل الفجوة قرارًا لا شكوى** |
| `offenderIds` | معرّفات المنتجات المتسبّبة (مرتّبة بالمعرّف — حتمية) |
| `fix` | `HarmonyFix?` — الإصلاح الملموس، أو `null` حين لا يوجد بديل حقيقي |

`HarmonyFix` يُبنى بإعادة استخدام `ReplacementFinder` القائم: البديل يجب أن يدخل الخانة نفسها،
وضمن الميزانية، وأن يرفع الدرجة فعلًا. **بديل لا يدخل الغرفة ليس إصلاحًا.**

> `null` مقصود: `UnmetNeed.tier` يُترك فارغًا حين لا تقدير موثوق، لأن «تقدير بلا مصدر أسوأ من
> لا تقدير» (`unmet_need.dart:72`). نفس المبدأ هنا.

### 5.1 مثال محلول — مثال البريف نفسه

خطة غرفة معيشة ٤×٥م، والمستخدم طلب `modern`:

| القطعة | ستايل | لون | خامة |
|---|---|---|---|
| كنب ثلاثي | modern | `gray_cool` (بارد) | fabric |
| طاولة قهوة جوزي | modern | `brown` (دافئ) | wood · جوز |
| سجادة | modern | `beige` (دافئ) | fabric |
| أباجورة أرضية | minimal | `black` | metal |

| البعد | الحساب | `sub` | `sub × w` |
|---|---|:--:|---:|
| `styleCoherence` | ٣ أزواج ١٠٠ + ٣ أزواج ٨٠ → ٥٤٠÷٦ | 90 | 2700 |
| `colorHarmony` | **C2**: المسيطر `gray_cool` بارد، الثانوي `brown` دافئ → −60 | 40 | 1000 |
| `materialBalance` | نغمة خشب واحدة · نسيج موجود · خشونة موافقة | 100 | 2000 |
| `formBalance` | **S2**: نطاق ارتفاع واحد → −20 | 80 | 1200 |
| `intentMatch` | ستايل الخطة `modern` = المطلوب | 100 | 1000 |
| **المجموع** | `7900 ÷ 100` | | **79** |

**الفجوة الأولى المعروضة:**

> **«الجوز الدافئ والرمادي البارد يتجاذبان — استبدل الكنب برمادي دافئ لترفع التناغم +١٥.»**
> `ruleId: 'C2'` · `gainIfFixed: 15` · `offenderIds: ['sofa_grey_3s']`
> `fix:` كنب بنفس المقاس والسعر بلون `gray_warm`

**التحقّق:** بعد الاستبدال `colorHarmony = 100` → `2500` بدل `1000`
→ `9400 ÷ 100 = 94` → **94 − 79 = +15** ✅

> الرقم المعروض للمستخدم مُشتقّ من الحساب نفسه، لا مكتوب في نصّ الرسالة. لا يمكن أن يكذب.

### 5.2 الترتيب حتمي

```dart
gaps.sort((a, b) {
  final byGain = b.gainIfFixed.compareTo(a.gainIfFixed);   // الأنفع أولًا
  if (byGain != 0) return byGain;
  final byRule = a.ruleId.compareTo(b.ruleId);              // فاصل ثابت
  if (byRule != 0) return byRule;
  return a.offenderIds.first.compareTo(b.offenderIds.first); // فاصل نهائي بالمعرّف
});
```
ثلاث طبقات فصل — لأن `List.sort` في Dart غير مستقرّة، ونفس المدخلات يجب أن تعطي نفس الترتيب
في كل تشغيل. نفس الانضباط في `replacement_finder.dart:80` و `placement_solver.dart:129`.

## 6) الحدّ المعماري — أين يقف هذا

- **التناغم `SOFT` لا `HARD`.** `knowledge_base.md:115` يصنّف `StyleHarmonyConstraint` تفضيلًا
  قابلًا للمقايضة. لا يمنع قطعة، ولا يحذفها، ولا يرفض خطة. **يُعلم، والمستخدم يقرّر.**
- **لا AI في أي سطر.** جداول ثابتة وحساب صحيح. النموذج لا يُسأل «هل هذا حلو؟».
- **Dart صرف.** بلا Flutter، بلا analytics — داخل حدّ `engine_purity_test`.
- **لا يُغرق المستخدم.** ثلاث فجوات معروضة كحدّ أقصى، والباقي خلف «المزيد».

## 7) الربط بالثقة — قرار يحتاج إقرارك

`_confidence()` اليوم = ٤٠ نواقص + ٢٥ ميزانية + ٢٠ مقاس + ١٠ توفّر + ٥ ملكية = ١٠٠.

| الخيار | الوصف | الأثر |
|---|---|---|
| **أ · إشارة موازية** ✅ *أرشّحه* | التناغم درجة مستقلّة بجانب الثقة | صفر تغيير على عقد قائم · اختباراته كلها تبقى خضراء · **تطوّر لا إعادة كتابة** |
| ب · دمج فوري | إعادة توزيع الـ١٠٠ لإفساح ١٠ للتناغم | يغيّر معنى رقم يراه المستخدم اليوم · يكسر اختبارات قائمة |

**التوصية: (أ).** الثقة تجيب «هل أخطأتُ خطأً محرجًا؟» — والتناغم يجيب «هل تبدو غرفتي مقصودة؟».
سؤالان مختلفان يستحقّان رقمين. الدمج يبقى ممكنًا لاحقًا ببيانات استخدام حقيقية.

## 8) خطة الاختبار (تُكتب بعد الموافقة)

| # | الاختبار | يثبت |
|---|---|---|
| ١ | `KA-ST1`: `affinity(modern,minimal) ≥ 70` و `affinity(modern,classic) ≤ 54` | اللغة تحقّق قاعدة معلنة سلفًا |
| ٢ | تناظر التقارب: `affinity(a,b) == affinity(b,a)` لكل ٣٦ زوجًا | سلامة رياضية |
| ٣ | المثال المحلول §5.1 يعطي `79` ثم `94` بعد الإصلاح | `gainIfFixed` ليس رقمًا مزخرفًا |
| ٤ | خطة بقطعتين → `notEnoughItems` بلا درجة | لا ١٠٠ مجّاني |
| ٥ | تشغيل نفس المدخلات ١٠٠ مرّة → ناتج متطابق بايتًا ببايت | حتمية |
| ٦ | ترتيب الفجوات ثابت عند تساوي `gainIfFixed` | فواصل التعادل تعمل |
| ٧ | كل `HarmonyGap.fix` يدخل الغرفة فعلًا (عبر `ArSpatialEngine`) | لا إصلاح وهمي |
| ٨ | كل `ruleId` منتَج له مدخل في مواصفة لغة التصميم | لا قاعدة بلا شرح |

الاختبار ٨ حارس بنيوي: **قاعدة بلا جملة تشرحها = صندوق أسود مرفوض.**
