# أنبوب الفهم — التركيب وحقن المزوّد وحدّ الخصوصية

> المسار ٣ (الفهم) · **مقترح بانتظار الموافقة** · يُرسمِن مرجعًا مذكورًا ٣ مرّات في
> `lib/ai/**` ولم يكن موجودًا (A-15). §٥ يحتاج موافقة مشتركة (٣+١+المعماري) بنصّ
> الميثاق §٥.٧ — لا أقرّره وحدي.

## ١) الأنبوب القائم

```
analyzeFromVoice(audioRef) ──► SpeechToTextService.transcribe ──┐
                                                                 ▼
analyzeFromText(text) ─────────────────► normalizeInput ──► NormalizedInput
                                                                 ▲   {rawText, source,
analyzeFromImages(refs, text) ─► VisionAnalysisService.analyze ──┘    visionSummary, imageRefs}
                                                                 │
                                                                 ▼
                                              LlmExtractionService.extract
                                        ┌──────────────┴──────────────┐
                              MockLlmExtractionService      RawLlmExtractionService
                                    (الافتراضي)          buildPrompt → complete → parser
                                                                 │
                                                                 ▼
                                                    BusinessRulesEngine.apply
                                                                 │
                                        ═════════ حدّ الملكيّة ═════════
                                                                 ▼
                                              المحرّك الحتمي — القرار والتوصيات
```

`finalizeManual(draft)` يمرّ بـ`rules.apply` مباشرة بلا LLM — مسارٌ سليم للإدخال اليدوي.

**ملاحظتان على القائم:**
- `_extract` يبني الـprompt الرسمي ويرمي نتيجته ثم يستدعي `llm.extract` (A-06).
- فشل الرؤية يصير `''` صامتًا (A-10): الصورة فشلت والاستخراج يمضي كأن لا صورة.
  المقترح: تسجيل الفشل في `analysis.missing_information` وإشارة `vision_failed`
  لمسار ٥ — بلا شاشة خطأ، فالتدهور الرشيق هو السلوك الصحيح هنا.

## ٢) نقطة التبديل — جاهزة كما وُصفت

```dart
// lib/core/di/providers.dart — القائم اليوم
speechToTextServiceProvider  → const MockSpeechToTextService()
visionAnalysisServiceProvider → const MockVisionAnalysisService()
llmExtractionServiceProvider  → MockLlmExtractionService(uuidFactory: …)
analysisRepositoryProvider    → AnalysisRepositoryImpl(speechToText:, vision:, llm:)
```

`AnalysisRepositoryImpl` يستقبل العقود حقنًا ولا يعرف أيّ تطبيق يعمل. **هذا يعني أن
حقن مزوّد حقيقي لا يحتاج لمس نقطة نداء واحدة** — الوعد في البريف صحيح ومحقَّق.

```dart
// جذر التركيب — موضع الـoverride الوحيد المسموح
ProviderScope(overrides: [
  llmExtractionServiceProvider.overrideWithValue(
    RawLlmExtractionService(complete: <محوّل المزوّد>),
  ),
])
```

| # | القاعدة |
|---|---|
| `O-1` | الـoverride في جذر التركيب وحده — لا في شاشة ولا متحكّم ولا اختبار يتسرّب للإنتاج |
| `O-2` | بلا override ⇒ لا خروج بيانات. الحالة الافتراضية آمنة **بالبناء** لا بالانضباط |
| `O-3` | المزوّد الحقيقي لا يُركَّب إلا بعقد خصوصية صريح (`Z-01`) — وسيط إجباري فالنسيان لا يُترجَم |

## ٣) `LlmComplete` — توسيع متوافق (A-09)

القائم: `typedef LlmComplete = Future<String> Function(String prompt);`
بلا مهلة ولا إلغاء ولا معرّف طلب ولا usage ولا سبب إنهاء. لا موضع لفرض حدّ.

**المقترح — توسيع لا استبدال**، يبقى التوقيع القديم صالحًا:

```
LlmRequest  { promptText, promptVersion, jsonSchema?, maxOutputTokens, timeout, requestId }
LlmResult   { text, finishReason(complete|truncated|refusal), usage? }
LlmComplete = Future<LlmResult> Function(LlmRequest)
```

- `finishReason: refusal` يُخطَّط إلى فشل مستقلّ **قبل** أيّ محاولة تحليل.
- `usage` عدّادات مجرّدة فقط — لا يعبر عبره محتوى.
- `requestId` عشوائي لكلّ طلب، **بلا اشتقاق من هويّة أو جهاز** (`Z-06`).
- تفاصيل المزوّد كلّها (العنوان، الترويسات، شكل الجسم) تُحبَس داخل المحوّل ولا تتسرّب
  فوق هذا الحدّ — شرط قابلية التبديل.

**A-08 يُصلَح هنا:** سقوط الشبكة يعود `NetworkFailure` (موجود في `failure.dart`)
لا `AiParsingFailure`، فيميّز المستدعي «الشبكة سقطت» عن «المزوّد أخرج فسادًا» —
وهما يستحقّان معالجتين مختلفتين. والاختبار الذي يثبّت الخطأ الحالي يُحدَّث معه.

## ٤) مراحل الطرح

| المرحلة | ما يعمل | البوّابة |
|---|---|---|
| ٠ | mock فقط — الوضع الحالي | — |
| ١ | تصليب المُحلِّل (`H-10`/`H-11`) + الاختبار البديل + وصل القالب الواحد (`P-01`) | موافقتك على هذه المستندات |
| ٢ | مزوّد LLM حقيقي، **نصًّا فقط**، بيئة تطوير، مفتاح تطوير | إقرار §٥ + §٦ من `prompt_engineering.md` |
| ٣ | الصورة: `visionSummary` المشتقّ فقط، بلا بايتات | spec خصوصية ٣+١ يوافق عليه المعماري |
| ٤ | الصوت | إقرار صريح منفصل — أخطر فئة |

المرحلة ١ وحدها **لا تحتاج مزوّدًا** وتغلق الثغرة الجوهرية. هذا أهمّ ما في الجدول:
الميثاق §٧ يقول «الفهم نائم حتى مزوّد LLM حقيقي» — والصحيح أن **إغلاق A-01 لا ينتظر
المزوّد، بل يجب أن يسبقه.**

## ٥) حدّ الخصوصية — spec مشترك (٣ + ١) يوافق عليه المعماري

بنصّ الميثاق §٥.٧: صورة غرفة المستخدم تدخل عبر مساري (فهمًا وتطبيعًا)، وتوليد مسار ١
يستهلك مخرجاتها عبر عقد، **وحدّ الخصوصية spec مشترك**. ما يلي مقترحي كطرفٍ واحد.

### ٥-١ تصنيف البيانات والخروج الافتراضي

| الفئة | مثال | الحسّاسية | الخروج الافتراضي |
|---|---|---|---|
| A | بايتات الصوت الخام | حرجة | **لا يخرج** |
| B | بايتات الصورة الخام | حرجة | **لا يخرج** |
| C | النصّ المنسوخ من الصوت | مرتفعة | بموافقة صريحة للفئة |
| D | `visionSummary` المشتقّ | متوسطة | يخرج بعد التنقيح |
| E | `rawText` | متوسطة | يخرج بعد التنقيح |
| F | `FurnishingProject` المنظّم | منخفضة | يبقى محلّيًّا |
| G | عدّادات وأزمنة | منخفضة | يخرج بلا محتوى |

**القاعدة: يخرج المشتقّ المحدود (D, E) لا الوسائط الخام (A, B).**

### ٥-٢ القواعد

| # | القاعدة |
|---|---|
| `Z-01` | لا يُبنى مزوّد حقيقي بلا عقد خصوصية صريح: فئات مسموحة · احتفاظ · إقليم · استثناء من التدريب. وسيط إجباري في المُنشِئ |
| `Z-02` | بايتات A وB لا تخرج افتراضيًّا؛ تشغيل كلٍّ منهما بند موافقة **مستقلّ** لا موافقة عامّة |
| `Z-03` | تنقيح قبل الخروج على D وE (هاتف/بريد/هويّة/IBAN). **التنقيح ناقص بطبيعته ولا يبرّر توسيع الخروج** |
| `Z-04` | لا تسجيل محتوى في السجلّات — لا `rawText` ولا `visionSummary` ولا نصّ الاستجابة، ولا حتى عند الخطأ. المسموح: بصمة، حجم، مدّة، معرّف قاعدة |
| `Z-05` | لا احتفاظ بالوسائط الخام بعد الجلسة ولا كتابتها على قرص |
| `Z-06` | `requestId` عشوائي بلا معرّف مستقرّ يعبر إلى المزوّد |
| `Z-07` | مفتاح ماحٍ في الإعداد يعيد الكلّ إلى mock بلا نشر جديد |
| `Z-08` | كلّ خروج يولّد أثر تدقيق محلّيًّا **بلا محتوى**. تعريف الحدث لمسار ٥ — أعلن الحاجة ولا أعرّفه (الميثاق §٥.٥) |
| `Z-09` | موافقة صريحة لكلّ فئة قبل أوّل خروج، قابلة للسحب، والسحب يعيد الطبقة إلى mock فورًا. **المخزن والمتحكّم لمسار ٥** (§٥.٦) — أستهلك بوّابته ولا أبنيها |
| `Z-10` | مزوّد لا يدعم استثناء التدريب والاحتفاظ القصير **لا يُعتمَد** — مانعٌ لا ملاحظة |

### ٥-٣ ما لا أحسمه

الالتزام التنظيمي (PDPL — مسار ٥) والسوق ووجود قاصرين تحدّد أيّ صفٍّ في ٥-١ هو
الافتراضي عمليًّا. أعلن الحاجة ولا أخمّن.
