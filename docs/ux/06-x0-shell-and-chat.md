# X0 — الهيكل الثلاثي بالسحب وصفحة المحادثة
## لقطة تصميم موجزة · التوجيه نفسه موافقةٌ على البنية

> يحلّ محلّ §٤ (التنقّل) من `05-vision-redesign.md`. بقيّة 05 تبقى تحت مراجعة المؤسّس.

---

## ١) الهيكل

```
RTL — الأولى يمين:        [ ٣ المعاينة ] [ ٢ غرفتي ] [ ١ المساعد ]
                                                          ▲ الفتح يهبط هنا
```
`PageView` أفقي واحد. الاتجاه يأتي مجّانًا: التمرير الأفقي يحترم `Directionality`،
فالصفحة صفر تقع **يمينًا** بلا عكسٍ يدوي.

**الروابط العميقة تبقى.** الثلاثة تبني **نفس** الهيكل بصفحةٍ مختلفة، وتتشارك مفتاح
صفحةٍ واحدًا (`ValueKey('experience-shell')`) فيراها الـNavigator صفحةً واحدة تُحدَّث
لا ثلاثًا تُستبدل — فتبقى حالة الهيكل والمحادثة عبر التنقّل:

| المسار | الصفحة |
|---|---|
| `/` | يُحوّل إلى `/assistant` (الباب لم يعد وجهة) |
| `/assistant` · `/room` · `/preview` | ٠ · ١ · ٢ داخل الهيكل |
| `/assistant/manual` · `/assistant/thinking` | **تُدفَع فوق** الهيكل (`push`) — ولها زرّ رجوع تلقائي |

المسارات تبقى **مسطّحة**: لا `StatefulShellRoute` ولا تعشيش. `router_test` يبقى حارسًا.

## ٢) حارس القِمع — شرط القبول

`PageView` يبني الصفحة المجاورة أثناء السحب. لو بُني `PlanScreen` هكذا، لأُطلق
`plan_seeded` قبل أن يصل المستخدم — وهو بالضبط ما منعه تسطيح المسارات في ADR-0002.

**القاعدة:** الصفحة تُركَّب حين **تستقرّ** لا حين تُلمَح.
- `_mounted` تبدأ بصفحة الدخول وحدها.
- `ScrollEndNotification` ⇒ تُقرأ الصفحة المستقرّة ⇒ تُضاف إلى `_mounted` ⇒ تُركَّب.
- ما لم يُركَّب يعرض هيكلًا محايدًا (إطارًا لدقيقةٍ بصرية واحدة).
- `PlanScreen` وحده يراقب `planControllerProvider`، و`PlanController` وحده يُطلق
  `PlanSeeded` ⇒ **لا تركيب، لا حدث**.

**الاختبار:** الفتح والبقاء على المساعد ⇒ لا `PlanSeeded` مطلقًا؛ السحب حتى الاستقرار
على «غرفتي» ⇒ يُطلق مرّة واحدة.

## ٣) صفحة المحادثة (تحويل لا بناء)

`AssistantScreen` اليوم تملك ما نحتاجه: `runText` · `runVoice` · `runImages` ·
حارس «لا إرسال بلا وصف». يتغيّر **العرض** لا المنطق.

```
┌──────────────────────────────────────────┐
│  [ بانر الموافقة — حتى يختار ]           │
│                                          │
│  ┌────────────────────────────────────┐  │
│  │ صف غرفتك وميزانيتك بكلماتك،        │  │ ← تحية (رسالة مساعد)
│  │ وأبني لك أوّل خطة تشكّلها.          │  │
│  └────────────────────────────────────┘  │
│                                          │
│         ┌──────────────────────────────┐ │
│         │ غرفة نوم ٤×٣٫٧، ميزانيتي     │ │ ← رسالة المستخدم
│         │ ٣٠٠٠، أبي سرير وكنب          │ │
│         └──────────────────────────────┘ │
│                                          │
│  ┌────────┐                              │
│  │ ● ● ●  │  ← «التفكير» مؤشّر كتابة     │
│  └────────┘     لا شاشة مستقلّة           │
│                                          │
├──────────────────────────────────────────┤
│  📷   🎙   [ اكتب…              ]   ◀    │ ← شريط الإدخال السفلي
│              إدخال مفصّل بالحقول          │
└──────────────────────────────────────────┘
```

**السلوك:**

| الحالة | ما يحدث في المحادثة |
|---|---|
| إرسال نصّ | فقاعة المستخدم ← `runText` ← مؤشّر كتابة |
| 🎙 / 📷 | فقاعة «رسالة صوتية» / «صورة الغرفة» ← `runVoice`/`runImages` (محاكاة اليوم، معلَّمة تجريبيًّا) |
| `ready` | «خطتك جاهزة» ثم **انتقال تلقائي إلى غرفتي** |
| `needsFollowUp` | «أحتاج تفاصيل قصيرة» ثم **دفع** `AnalysisScreen` — نموذج الأسئلة القائم يُعاد استعماله كما هو |
| `error` | فقاعة مساعد بالرسالة، والمحادثة تبقى مفتوحة لإعادة المحاولة |

القائمة `reverse: true` فالأحدث أسفل بلا متحكّم تمرير.

**قراران اتّخذتهما، يسهل نقضهما:**
1. **الباب يُحوَّل لا يُحذف.** `OnboardingScreen` تصير غير مقصودة، وبانر الموافقة
   ينتقل إلى المحادثة كما يطلب التوجيه. لم أحذف الملف — مصيره فرزُ ملفّات للمعماري.
   والدخول المجهول لا يقرؤه أحد (`currentUser` بلا مستهلك في `lib/` كلّه)، فنقله
   لا يفقد سلوكًا.
2. **«التفكير» لم يُحذف — تغيّر دوره.** صار مؤشّر كتابة داخل المحادثة، وبقيت
   `AnalysisScreen` لأسئلة المتابعة وحدها حيث هي أقوى ما تكون. تطوّرٌ لا إعادة كتابة.
