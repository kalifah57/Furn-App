# عقد استهلاك نظام التصميم — بين مسار ١ (التصميم) ومسار ٤ (التجربة)
## المسار ٤ (التجربة/UX) · التسليم ٤

> **حالة العقد: مقترح.** يحتاج موافقة المؤسّس + مالك مسار ١ + المعماري (لأنه يقترح
> إسناد ملكية ملف). كُتب من طرف المستهلك: هذا ما **تحتاجه** الشاشات، لا ما ينبغي أن
> يكون عليه نظام التصميم — تعريف اللغة نفسها لمسار ١ وحده.

---

## ١) الحالة اليوم — لماذا نحتاج عقدًا أصلًا

| الحقيقة | الأثر |
|---|---|
| `lib/domain_engine/design/` **غير موجود** في هذا الفرع | لا tokens تُستهلك بعد |
| مخرجات مسار ١ (`docs/design/01-design-language.md` …) على فرع `claude/furn-app-design-engineer-ejxml4` غير المدموج | العقد يُكتب الآن ليجهز ساعة الدمج |
| `app_theme.dart` كل هويّته بذرة لونية واحدة `0xFF7A5C3E` + أنصاف أقطار ثابتة (16/14/12/10) | لا مقياس مسافات، لا سلّم خطوط، لا ألوان دلالية |
| **٩ ألوان ثابتة** خارج `ColorScheme` في `plan_screen.dart` (`Colors.green/orange/red`) | لا تستجيب للوضع الداكن ولا للتباين — وهي **لغة تصميم مكتوبة في شاشة** |
| `fontFamily = null` (`app_theme.dart:12`) | العربية تُصيَّر بخط النظام؛ سلّم الخطوط قرار مؤجّل |

الألوان التسعة الثابتة هي بالضبط ما يعالجه هذا العقد: هي **معنى** (إيجابي/انتباه/سلبي)
لبسته الشاشة لونًا من عندها. المعنى لي، واللون لمسار ١.

## ٢) الملكية — الحدّ المقترح

القاعدة الذهبية «ملف واحد = مالك واحد» تترك `lib/core/theme/` بلا مالك في جدول
الميثاق §٢. المقترح:

| الطبقة | الملف | المالك | لماذا |
|---|---|---|---|
| **القيم والقواعد** | `lib/domain_engine/design/tokens.dart` *(جديد)* | **مسار ١** | لغة التصميم — Dart صرف، قابل للاختبار |
| **الربط بـMaterial** | `lib/core/theme/app_theme.dart` + `design_tokens_theme.dart` *(جديد)* | **مسار ٤** | ربطٌ تقني بـFlutter، لا حكم تصميمي |
| **الاستهلاك** | `lib/features/*/presentation/**` | **مسار ٤** | الشاشات |
| **الرسم** | `sandbox_scene_view.dart` | **مسار ١** | المشهد نفسه |

**الاتجاه — أهمّ سطر في العقد:**
> مسار ١ يقرّر **ما هي القيمة**. مسار ٤ يقرّر **أين تُستعمل**. لا أحد يعبر.

نتيجتان عمليتان: لا أكتب لونًا جديدًا في شاشة ولو مرّة واحدة (وأسدّد الألوان التسعة
القائمة)؛ ولا يفتح مسار ١ ملف شاشة ليغيّر مظهرها — يغيّر القيمة فيتغيّر كل مستهلكيها.

### قيد صلب: المحرّك يبقى صرفًا
`engine_purity_test.dart` يمنع استيراد Flutter داخل `lib/domain_engine/`. لذلك
`tokens.dart` **لا يستورد `material.dart`**: الألوان `int` بصيغة ARGB، والمسافات
`double`. التحويل إلى `Color`/`EdgeInsets` يقع عندي في `core/theme`. هذا ليس التفافًا
على القيد بل احترامه: لغة التصميم قواعد، لا ودجات.

```dart
// lib/domain_engine/design/tokens.dart  — مسار ١ — Dart صرف
abstract final class DesignTokens {
  static const int surfaceSeed = 0xFF7A5C3E;
  static const int statusPositive = 0xFF2E7D32;
  static const double spaceMd = 12;
  // …
}
```
```dart
// lib/core/theme/design_tokens_theme.dart — مسار ٤ — الربط
class FurnTokens extends ThemeExtension<FurnTokens> {
  const FurnTokens({required this.statusPositive, required this.spaceMd, ...});
  factory FurnTokens.from(Brightness b) => FurnTokens(
        statusPositive: Color(DesignTokens.statusPositive), ...);
  // copyWith + lerp
}
```
الشاشة تقرأ `Theme.of(context).extension<FurnTokens>()!.statusPositive` — فتنتقل أي
قيمة تتغيّر عند مسار ١ إلى كل شاشة بلا لمس ملف واحد عندي.

## ٣) ما أحتاجه بالضبط — قائمة الطلب

مرتّبة بالحاجة الفعلية للشاشات القائمة، لا بما هو ممكن. **[ح]** = حاجب لمرحلة ٥ز
(الوصول) في خريطة التجربة.

### ٣.١ ألوان دلالية **[ح]**
تحلّ محلّ الألوان التسعة الثابتة. كلٌّ بقيمتين (فاتح/داكن) وتباينٍ مضمون ≥ 4.5:1 مع
سطحه:

| الرمز | معناه عندي | مستهلكوه اليوم |
|---|---|---|
| `statusPositive` | ضمانٌ متحقّق · وفّرت · بديل أرخص · لحظة الوصول | `plan_screen.dart:197,285,682,713,812,814,980,987` |
| `statusAttention` | ضمان غير متحقّق · ثقة متوسطة | `plan_screen.dart:197,285` |
| `statusNegative` | خارج الميزانية · تجاوز | موجود كـ`colorScheme.error` — يبقى |
| `confidenceLow / Mid / High` | تدرّج حلقة الثقة | `plan_screen.dart:196` |
| `pinnedAccent` | القطعة المثبّتة | `plan_screen.dart:519` (`Colors.red` اليوم) |

> **العتبات التي تختار بينها ليست لك ولا لي** — هي من المحرّك (ح-٧). أنت تعطيني
> ثلاثة ألوان، والمحرّك يقول أيّها ينطبق.

### ٣.٢ مقياس المسافات **[ح]**
`space2xs · xs · sm · md · lg · xl · 2xl` بقيم ثابتة. اليوم في الشاشات ١٦ قيمة
مسافة مختلفة مكتوبة يدويًّا (4، 6، 8، 10، 12، 14، 16، 20، 22، 24، 32…). أحتاج سلّمًا
أُسنِد إليه كل حشوة.

### ٣.٣ أنصاف الأقطار والارتفاعات
`radiusSm/Md/Lg/Pill` + `elevationCard/Sheet/BottomBar`. اليوم 10/12/14/16/999 متفرّقة.

### ٣.٤ سلّم الخطوط العربية
اسم العائلة + الأوزان + خريطة إلى `TextTheme`. القرار المعلّق في
`app_theme.dart:10-12` و`pubspec.yaml` (كتلة `fonts` معطّلة) **قرار مسار ١**، وأنفّذ
التفعيل عندي. الأهمّ: ارتفاع السطر (`height`) للعربية — الافتراضي اللاتيني يضغط
التشكيل والنقاط.

### ٣.٥ مكوّنات مشتركة
لا أطلب مكتبة مكوّنات. أطلب **قيم** المكوّنات القائمة (البطاقة، الزرّ الممتلئ، الحقل،
الشريحة، الورقة) لأضبط بها `ThemeData` مرّة واحدة، فتتبعها كل الشاشات. المكوّنات
نفسها تبقى Material قياسية — «تطوّر لا إعادة كتابة».

### ٣.٦ نموذج «تناغم الغرفة» — العقد المستقبلي
حين ينضج، أستهلكه **بنفس شكل `ConfidenceGap` حرفيًّا**:

```dart
class HarmonyGap {
  final String label;        // «الجوز والرمادي البارد يتجاذبان في اتجاهين»
  final int points;          // +15
  final List<String> actions;// «استبدله برمادي دافئ»
}
```
لأنّ الشاشة تعرفه فورًا: تصييره نسخة من `_nextSteps` (`plan_screen.dart:201`) بلا
مكوّن جديد. **الشرط الوحيد:** كل جملة جاهزة للعرض بالعربية من المحرّك — لا أصوغ أنا
جملة تصميم، ولا أفسّر درجة.

**سؤال مفتوح لمسار ١:** أين يظهر التناغم في «غرفتي»؟ حلقة ثانية بجانب الثقة تُنقص
وضوح الرقم الواحد الذي هو نتيجة المنتج. أرشّح **سطرًا داخل «لترفع ثقتك»** ما دام
التناغم لا يدخل في حساب الثقة، ومراجعة الموضع إن دخل.

## ٤) كيف تتدفّق القيمة — المسار كاملًا

```
مسار ١: قاعدة تصميم مُختبَرة
   └─▶ domain_engine/design/tokens.dart        (Dart صرف · int/double)
          └─▶ core/theme/design_tokens_theme.dart   (مسار ٤ · ThemeExtension)
                 └─▶ core/theme/app_theme.dart      (مسار ٤ · ThemeData)
                        └─▶ الشاشات                  (Theme.of(context))
```

**اختبار يحرس العقد** (أكتبه أنا، مرحلة ٥ز):
`test/features/design_tokens_test.dart` — لا لون حرفيّ في `lib/features/*/presentation/`
خارج `ColorScheme` أو `FurnTokens`. يفشل CI عند أوّل `Colors.green` جديد. حارسٌ من
نوع `router_test`: يمنع الانحراف الذي لا يمسكه المترجم.

## ٥) ما لا أفعله — ضمانات مسار ٤ لمسار ١

1. لا أُعرّف لونًا ولا خامة ولا ستايلًا ولا قاعدة تناغم.
2. لا أصوغ جملة حكم تصميمي — أعرض ما يخرج من المحرّك.
3. لا ألمس `sandbox_scene_view.dart`. أملك الشاشة حوله والتفاعل معه.
4. لا أضيف مكوّنًا بصريًّا جديدًا يحمل معنى تصميميًّا بلا token يسنده.
5. لا أغيّر `tokens.dart` — أفتح طلبًا فيه الحاجة والمستهلك.

## ٦) ما أطلبه من مسار ١ مقابل ذلك

1. **أسماء ثابتة** لا تتغيّر بلا نسخة — إعادة تسمية token تكسر كل مستهلكيها.
2. **قيمتان لكل لون** (فاتح/داكن) وتباين مضمون — وإلّا انكسر الوضع الداكن.
3. **كل جملة معروضة جاهزة بالعربية** من طرفك.
4. **العتبات في المحرّك لا في الـtokens** — الـtoken لون، والقرار قرار.
5. **إخطار قبل تغيير قيمة** تمسّ الحالة (الألوان الدلالية) — قد يتغيّر معها معنى.

## ٧) بروتوكول التغيير

| نوع التغيير | من يبدأ | من يوافق |
|---|---|---|
| قيمة token قائم | مسار ١ | مسار ١ (إخطار مسار ٤) |
| token جديد | مسار ٤ (طلب) أو ١ (عرض) | مسار ١ |
| إعادة تسمية/حذف | مسار ١ | مسار ١ + ٤ + المعماري |
| شكل عقد (`HarmonyGap` مثلًا) | مسار ١ | ١ + ٤ + المعماري |
| ملكية ملف | أيّهما | **المعماري** |

كل تغيير يمرّ بالراسبتوري: spec في `docs/` ثم كود. لا لصق بين الشاتات.

## ٩) ما يجهز اليوم بلا مسار ١

حتى يُدمج فرع التصميم، هذه المراحل **غير محجوبة** وتمضي:
٥أ (لا طريق مسدود) · ٥ب (سداد دَين القرار) · ٥ج (المعاينة تعرض خطتك) ·
٥د (صدق الإدخال) · ٥هـ (توحيد النصّ) · ٥و (ترتيب غرفتي) · ٥ح (الحالات) ·
٥ط (الاختبارات).

المحجوب جزئيًّا: **٥ز** وحدها — وجزؤها الدلالي (`Semantics`) غير محجوب أصلًا، فيمضي
معها. أي أن انتظار مسار ١ لا يوقف شيئًا من العلاج العاجل.
